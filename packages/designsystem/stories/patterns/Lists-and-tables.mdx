# Lists and tables

## 1. Choose

| It is | Use |
| --- | --- |
| Things the reader opens, each with a name and a line under it | `List` (one column, name strongest; `kind` gives the picture in front) |
| Pictures that are the content, looked at (a cast, an artist's albums) | `Tiles` |
| Things with several figures to compare down a column | `Table` |
| Hundreds of rows | the first ones, and «Se alle» to a page with the rest |

## 2. Order and size

- Default to the most recent first, or alphabetical by the first column (Primer, data table).
- Start cutting at about 20 rows. Before that, show them all.
- A sorted column says so (`aria-sort`), and the sort is a link, so the sorted page has an address.
- Leave an empty cell empty; never a dash (Primer).

## 3. Find

<SearchField label="Søk i listen" action="#" />

A short list needs nothing. A list of a few known values has `FilterChips`. A long list has a `SearchField` above it, and says how many
there were («5 treff»). When filters are active, say so: «2 filtre er på. Nullstill.»

## 4. Long lists

The design system has no pagination: a list on a front page shows its first few and links to its own page with all of them («Se alle»), and that
page holds them all. Nothing is announced when content arrives within 750 ms (Primer, data table accessibility).

## 5. States

- **Loading:** a `Skeleton` that matches the column widths and the height of a row, so nothing jumps.
- **Empty:** an `EmptyState` with its `reason` (`no-results` after a search or a filter); no table headers over no rows.
- **Error:** an `ErrorMessage` in the part that failed (a `PageSection` with `what` and `error`).

## 6. A narrow window

Keep the key columns and scroll the rest sideways inside a focusable wrapper, or drop the least important columns (Primer). A list of
text is never put in columns; on a phone `List` is already one column.
